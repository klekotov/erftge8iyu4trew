# JSON-лоты для плагина Lots Copy (`/create_lots`) — разбор всех полей

Документ описывает файл, который плагин **Lots Copy Plugin** принимает командой `/create_lots`
и отдаёт командой `/cache_lots`. Всё ниже сверено с кодом плагина и с кодом `FunPayAPI`,
который лежит в этом же репозитории (папка `FunPayAPI/`).

**TL;DR — четыре правила, на которых спотыкаются чаще всего:**

1. `node_id` — ID раздела из ссылки `funpay.com/lots/<ID>/trade`; от него зависит, какие
   ещё поля (`fields[type]`, `fields[server]`, …) обязательны. Их берут из формы раздела.
2. `active` должно быть ровно `"on"` (иначе лот создастся выключенным), `price` — с точкой
   (`"199"`, `"199.50"`), `amount` — только целое (`"9999"`).
3. `auto_delivery` / `deactivate_after_sale`: **любая непустая строка = включено**
   (`"0"`, `"off"`, `"no"` тоже включают). Выключить = `""` или убрать ключ.
4. `csrf_token` и `offer_id` в файле не нужны, `deleted` — всегда `""`,
   `form_created_at` — не трогать (плагин отправляет как есть).

Готовые примеры файлов:
[`docs/examples/lots_example.json`](examples/lots_example.json) — 2 учебных лота,
[`docs/examples/cdt_cars_lots.json`](examples/cdt_cars_lots.json) — 13 реальных лотов
Car Dealership Tycoon (цены и обоснование: [`cdt_cars_price_list.md`](cdt_cars_price_list.md)).
Проверка/генерация: [`tools/lot_json_tool.py`](../tools/lot_json_tool.py).

## 1. Коротко: что вообще происходит с файлом

```
Telegram (/create_lots)
   │  скачивает файл → storage/cache/lots.json
   ▼
плагин:  for i in data:  lot = FunPayAPI.types.LotFields(0, i)
   │      create_lot(): fields["offer_id"] = "0"
   │                    fields["csrf_token"] = acc.csrf_token
   ▼
FunPayAPI.types.LotFields        ← здесь JSON-словарь разбирается по свойствам
   │      renew_fields()
   ▼
FunPayAPI.account.save_offer()   → POST https://funpay.com/lots/offerSave
```

Ключевые места в коде:

| Что | Где |
|---|---|
| Создание лота из элемента JSON | `copylotsplugin.py` → `create_lots()` → `create_lot()` |
| Разбор полей JSON в свойства | `FunPayAPI/types.py` → `LotFields.__init__` (стр. 833–875) |
| Обратная сборка полей перед отправкой | `FunPayAPI/types.py` → `LotFields.renew_fields()` (стр. 932–969) |
| Отправка на FunPay | `FunPayAPI/account.py` → `save_offer()` (стр. 1828–1861) |
| Как получается «эталонный» JSON | `FunPayAPI/account.py` → `get_lot_fields()` (стр. 1763–1814) |
| Загрузка картинки и получение её ID | `FunPayAPI/account.py` → `upload_image(..., type_="offer")` (стр. 766) |

**Главное следствие:** JSON — это не «мой формат», это почти-direct дамп HTML-формы
`https://funpay.com/lots/offerEdit`. Поэтому в файле есть служебные поля
(`form_created_at`, `query`, `location`, `node_id`), и они должны оставаться такими,
какими их отдал FunPay.

## 2. Таблица всех полей

| Поле | Тип | Что означает | Допустимые значения | Обязательно |
|---|---|---|---|---|
| `node_id` | строка-число | ID **раздела** (подкатегории) FunPay, куда создаётся лот. Берётся из ссылки `https://funpay.com/lots/<node_id>/trade` | `"1089"` | **Да** |
| `active` | строка | Публиковать лот сразу (галочка «Активен») | ровно `"on"` = включён, `""` = лот создаётся выключенным | Да (иначе выключен) |
| `price` | строка | Цена за 1 шт в валюте аккаунта | `"199"`, `"199.50"` (точка, без пробелов) | **Да** |
| `amount` | строка-число | «Наличие» — сколько штук в лоте | `"9999"` (только целое) | Нет (если в разделе нет наличия — ключ вообще убрать) |
| `deactivate_after_sale` | строка | «Отключать лот после продажи» | `""` = выкл, `"on"` = вкл | Нет |
| `auto_delivery` | строка | Включить **встроенную** автовыдачу FunPay | `""` = выкл, `"on"` = вкл | Нет |
| `secrets` | строка | Товары встроенной автовыдачи, по одному в строке (разделитель `\n`) | `"код1\nкод2"` | Нет (нужно при `auto_delivery: "on"`) |
| `fields[summary][ru]` | строка | Краткое описание (название лота) RU | текст | Да |
| `fields[summary][en]` | строка | Краткое описание (название лота) EN | текст | Желательно |
| `fields[desc][ru]` | строка | Полное описание RU | текст, `\n` = перенос строки | Да |
| `fields[desc][en]` | строка | Полное описание EN | текст | Желательно |
| `fields[payment_msg][ru]` | строка | Сообщение покупателю после оплаты (RU) | текст, можно ссылку | Нет |
| `fields[payment_msg][en]` | строка | То же на EN | текст | Нет |
| `fields[images]` | строка | ID картинок лота через запятую | `"123456,789012"` | Нет |
| `fields[...]` (прочее) | строка | Поля конкретного раздела: `fields[type]`, `fields[server]`, `fields[side]`, `fields[method]`, `fields[time]`, … | значения из списка раздела | Зависит от раздела |
| `form_created_at` | строка-число | Служебная метка времени формы (unix). Плагин отправляет как есть | `"1716550274"` | Формально да, не трогать |
| `query` | строка | Служебное поле формы (поиск/выбор раздела) | `""` | Нет |
| `location` | строка | Служебное скрытое поле формы | `""` | Нет |
| `deleted` | строка | Флаг удаления лота | **всегда `""`** | Нет |
| `csrf_token` | — | Подставляется автоматически токеном аккаунта | **не хранить в файле** | Нет |
| `offer_id` | — | Плагин сам ставит `"0"` = «создать новый» | **не хранить в файле** | Нет |

## 3. Что реально уходит на FunPay (проверено на вашем файле)

Я прогнал ваш `rty5w3ryt.json` через настоящий `LotFields.renew_fields()` из этого репозитория.
На `POST /lots/offerSave` уходит вот такой набор (сравните с исходником — часть полей меняется):

```json
{
  "active": "on",
  "deactivate_after_sale": "",
  "query": "",
  "form_created_at": "1716550274",
  "node_id": "1089",
  "location": "",
  "deleted": "",
  "fields[summary][ru]": "💎АВТОВЫДАЧА💎 🔥 ПРИВЯЗКА УЧЕТНОЙ ЗАПИСИ BATTLE NET 🔥 ✅БОНУС",
  "fields[summary][en]": "💎AUTO-ISSUE💎 🔥 LINKING A BATTLE NET ACCOUNT 🔥 ✅BONU",
  "auto_delivery": "",
  "price": "1.0",
  "amount": 9999,
  "fields[desc][ru]": "после оплаты вы получаете:\nтекстовый файл \"Гайд по привязке учетной записи Battle net\"",
  "fields[desc][en]": "after payment you receive:\ntext file \"Guide for linking a Battle net account\"",
  "fields[payment_msg][ru]": "спасибо за покупку, …",
  "fields[payment_msg][en]": "thank you for your purchase, …",
  "secrets": "",
  "offer_id": "0",
  "fields[images]": "",
  "csrf_token": "<токен вашего аккаунта>"
}
```

На что тут смотреть:

* `price` из `"1"` превратился в `"1.0"` — FunPayAPI всегда хранит цену как `float`
  и отправляет `str(float)`. FunPay такое принимает (ваш лот это подтверждает).
* `amount` уходит числом (`9999`), а не строкой — тоже нормально.
* Часть служебных полей FunPayAPI пересобирает сам (`auto_delivery`, `deactivate_after_sale`,
  `secrets`, `deleted`, `fields[images]`, `offer_id`, `csrf_token`) — даже если в файле их нет.
* `csrf_token` и `offer_id` взяты не из файла, а из аккаунта и из логики плагина.

## 4. Разбор по полям (с подводными камнями)

### `node_id` — раздел, куда создаётся лот

* Это ID **подкатегории** FunPay. Откройте раздел, где хотите продавать:
  `https://funpay.com/lots/<node_id>/trade` — число из ссылки и есть `node_id`
  (у вас `1089`).
* По этому полю FunPay решает, какая форма/какие обязательные поля нужны.
  Если `node_id` не соответствует набору полей в JSON — FunPay вернёт ошибку сохранения,
  и плагин напишет «❌ Не удалось создать лот … Ошибка: …».
* Также именно `node_id` плагин использует в тексте ошибки, чтобы показать вам раздел
  (`cardinal.account.get_subcategory(...)`).
* Лоты валютных разделов (chips) этим плагином не создаются вообще: `save_offer` для них
  ходит на другой эндпоинт (`chips/saveOffers`), а плагин всегда создаёт `LotFields`.

### `active` — публикация

`LotFields.active = (fields.get("active") == "on")`. Поэтому:

| В JSON | Результат |
|---|---|
| `"on"` | лот создаётся **активным** |
| `""` | лот создаётся **выключенным** (черновик в списке лотов) |
| `"1"`, `"ON"`, `"true"`, `true` | лот создаётся **выключенным** (тихо, без ошибки) |

Проверено: `"1"` и `"ON"` → в POST уходит `active: ""`.

### `price` — цена за 1 шт

* Валюта — валюта аккаунта (в конфиге/профиле FunPay), отдельного поля валюты нет.
* Разделитель — **точка**. `"199.50"` → ок. `"199,5"` → плагин упадёт с
  `ValueError: could not convert string to float` ещё до запроса, и вы увидите
  просто «❌ Не удалось создать лот …» без пояснения.
* Пробелы (`"1 000"`), `"₽"`, `"1 000,50"` — тоже ошибка.
* `price: ""` (пусто/нет ключа) → уйдёт пустая цена, FunPay не сохранит лот.
* Отрицательные и нулевые значения код не проверяет — отклонит уже FunPay.

### `amount` — наличие

* Только целое: `"9999"`. `"9999.0"`, `"9 999"`, `"много"` → `ValueError` в `int()`.
* Число в JSON (`9999`) допустимо, FunPayAPI сконвертирует.
* `"0"` или `""` → уйдёт пустое значение; лот будет выглядеть как «нет в наличии»
  либо FunPay сразу его выключит.
* **Если в разделе нет «Наличия»** (например, лоты-услуги/аккаунты, где 1 лот = 1 товар) —
  ключ `amount` лучше вообще убрать из JSON: `renew_fields()` тогда не отправит это поле
  (проверено: при отсутствии ключа поле в POST не попадает).
* Если включена встроенная автовыдача (`auto_delivery: "on"`), фактическое наличие
  FunPay считает по количеству строк в `secrets`, а не по `amount`.

### `deactivate_after_sale` — «Отключать лот после продажи»

Логика кода: `bool(поля["deactivate_after_sale"])`. То есть:

| В JSON | Что уйдёт | Итог |
|---|---|---|
| ключа нет | поле не отправляется | выключено (по умолчанию FunPay) |
| `""` | `""` | выключено |
| `"on"` | `"on"` | включено |
| `"0"`, `"off"`, `"no"`, `"false"` | `"on"` | **включено!** |

Это классическая ловушка: «выключить» можно только пустой строкой или удалением ключа.

### `auto_delivery` — встроенная автовыдача FunPay

Та же ловушка, что и выше: любая непустая строка = `"on"`.

Полезно понимать разницу:

* **Встроенная автовыдача FunPay** — товары лежат в поле `secrets` самого лота,
  FunPay выдаёт их сам. `auto_delivery: "on"` + непустой `secrets`.
* **Автовыдача Cardinal** — настраивается в `configs/auto_delivery.cfg` (или через ПУ в Telegram),
  товары лежат в `storage/products/*.txt`, а лот ищется по **названию**:
  `handlers.py → get_lot_config_by_name()` / `setup_event_attributes_handler()`
  (сначала точное совпадение названия лота, потом «начинается с», потом «содержит»).
  Если вы создаёте 50 лотов с разными названиями и хотите FPC-автовыдачу — в конфиге
  должно быть 50 секций, иначе бот не найдёт лот и напишет «Лот не найден в конфиге авто-выдачи!».

Для массовой загрузки обычно проще встроенная автовыдача FunPay: всё лежит в одном JSON.

### `secrets` — товары встроенной автовыдачи

* Строка, элементы через `\n` (в JSON это `"\n"`), например:
  `"login1:pass1\nlogin2:pass2"`.
* `renew_fields()` делает `"\n".join([i for i in secrets.strip().split("\n") if i])`:
  пустые строки выбрасываются, пробельные — тоже (элемент `"   "` не сохранится как товар).
* Список (`["a","b"]`) вместо строки → `AttributeError` и «❌ Не удалось создать лот».
* `secrets` без `auto_delivery: "on"` — товары сохранятся в лоте, но выдача останется
  ручной (FunPay будет ждать вас). Проверяйте оба поля вместе.

### `fields[summary][ru]` / `[en]` — краткое описание (название)

* Это то, что покупатель видит в списке лотов. Именно по нему FPC-автовыдача ищет
  конфиг лота (см. выше) — названия должны быть предсказуемыми.
* Длину код не проверяет; ограничение задаёт сайт (в HTML формы у поля есть `maxlength`,
  а при превышении FunPay вернёт ошибку текстом, и плагин покажет её как `Ошибка: …`).
* EN-версию лучше заполнять: англоязычные покупатели видят именно её.

### `fields[desc][ru]` / `[en]` — полное описание

* Обычный текст, `\n` — перенос строки.
* HTML-теги FunPay не рендерит как HTML — они останутся текстом.
* Кавычки внутри JSON обязательно экранировать: `\"`.

### `fields[payment_msg][ru]` / `[en]` — сообщение покупателю после оплаты

* Отправляется покупателю в чат автоматически после оплаты (встроенная функция FunPay,
  не Cardinal). Удобно для ссылки на гайд/инструкцию — как в вашем файле.
* В одном поле можно писать несколько строк через `\n`.

### `fields[images]` — картинки лота

* Формат: ID картинок через запятую: `"123456,789012"`.
* ID выдаёт сам FunPay при загрузке картинки:
  `account.upload_image("путь/к/картинке.png", type_="offer")` → `fileId` (см. `account.py:766`).
* Ключа нет → картинок у лота не будет (`renew_fields` подставит пустое значение).
* Нечисловое значение (`"abc"`) → `ValueError` и «❌ Не удалось создать лот».
* ID картинок выдаются аккаунту при загрузке, поэтому при переносе JSON с другого аккаунта
  (`/cache_lots` → `/create_lots`) их надёжнее очистить (`"fields[images]": ""`) и загрузить
  картинки заново тем аккаунтом, на который создаются лоты. Сами файлы плагин не переносит —
  только строку с ID.

### `fields[...]` — поля конкретного раздела ⚠️ самое важное для массовой загрузки

У игровых разделов (аккаунты, валюта, услуги) форма содержит дополнительные поля:
`fields[type]`, `fields[server]`, `fields[side]`, `fields[method]`, `fields[time]` и т. п.
Их значения должны быть **из списка допустимых** для этого раздела (`<select>`/`<input>` в форме).

Просто «придумать» их нельзя. Их надо брать из формы конкретного раздела:

```
GET https://funpay.com/lots/offerEdit?node=<node_id>
```

`FunPayAPI.account.get_lot_fields(0, node_id)` возвращает такой «пустой» шаблон раздела
(у него `offer_id = 0`). Именно так работает команда `template` в `tools/lot_json_tool.py`
(см. раздел 6) — она дополнительно выводит **подписи, обязательность и все допустимые
значения** каждого поля раздела.

Если в JSON подставить поле из другого раздела или недопустимое значение — FunPay вернёт
ошибку сохранения, плагин покажет её текст, лот будет пропущен.

#### Особая ловушка: общий раздел «Прочие игры» (`node_id` вида 402)

В общем разделе «Прочие игры» форма содержит дополнительные обязательные поля. Реальный
пример из выгрузки `/cache_lots` (раздел 402):

```json
"node_id": "402",
"fields[game]": "Car Dealership Tycoon",   // ИГРА — значение это подпись из списка, не ID
"fields[type]": "Предметы",                // ТИП предложения
"fields[method]": "Трейд",                 // способ передачи
"fields[name][ru]": "",                    // «Название» — необязательное, обычно пустое
"fields[name][en]": "",
```

Что важно:

1. **Значения берутся только из формы.** В этом разделе `fields[game]` — текст подписи,
   но в других разделах FunPay значения бывают числовыми (`"3928"`), поэтому угадывать нельзя.
   Отсутствие обязательного поля → FunPay подсвечивает «Заполните это поле», плагин пишет
   «❌ Не удалось создать лот … Ошибка: …».
2. **От `fields[game]` зависит видимость.** Покупатели фильтруют «Прочие игры» по игре:
   лот с чужим/пустым значением practically не показывается.
3. **Незнакомые FunPayAPI поля не теряются.** `LotFields` разбирает только свои свойства,
   а весь словарь целиком уходит в `POST /lots/offerSave`. Поэтому `fields[game]`,
   `fields[type]`, `fields[method]`, `fields[name][...]` доходят до FunPay как есть.
   (Проверено: после `renew_fields()` эти ключи на месте.)

Как получить значения без терминала — самый быстрый путь:

1. Создать один тестовый лот в нужном разделе вручную на сайте.
2. `/cache_lots` в боте → приходит `lots.json` с точным набором полей этого раздела.
3. Скопировать `fields[...]`, которые отличаются от стандартных (`summary`, `desc`,
   `payment_msg`), во все свои лоты.

Если терминал есть, это автоматизируется:

```bash
python tools/lot_json_tool.py template 402
python tools/lot_json_tool.py add-field lots.json "fields[game]" "Car Dealership Tycoon" --node 402
python tools/lot_json_tool.py validate lots.json --template template_402.json
```

`add-field` с `--node`/`--meta` сверяет значение со списком опций раздела и при опечатке
печатает допустимые; без метаданных пишет значение как есть (годится для свободных полей
вроде `"fields[platform]": "PC"`).

### `form_created_at` — служебная метка формы

* Unix-время генерации формы (`1716550274` = май 2024, у вас в файле именно оно).
* FunPay выдаёт новое значение при каждом `GET offerEdit`; по наблюдениям разработчиков
  сторонних клиентов FunPay (например, `funpay-mcp`) это значение нужно возвращать в форме
  сохранения, кэшировать его не следует.
* Плагин при `/create_lots` **не обновляет** это поле — отправляет то, что в файле
  (именно поэтому перенос лотов между аккаунтами и работает: значение из `/cache_lots`
  проходит). Если FunPay начнёт отвечать ошибкой формы — обновите `form_created_at`
  из свежего шаблона (`template`) и загрузите снова.

### `location`, `deleted` — служебные, но **ключ должен присутствовать**

Оба поля есть в каждой форме `offerEdit`, поэтому `/cache_lots` всегда выгружает их пустыми.
Значение — `""`, но **сам ключ в JSON должен быть**: если его нет, FunPay отвечает
`Ошибка: Заполните все поля.` и лот не создаётся. Проверено на разделе 402.

```json
"location": "",
"deleted": "",
```

* `deleted: ""` — «не удалять». Непустое значение = попытка удаления, для создания лота не годится.
* `query` — другое служебное поле (поиск в форме); присутствует в выгрузке, но пустое;
  на создание лота не влияет, можно оставить как есть или не добавлять.

### `auto_delivery`, `deactivate_after_sale`, `fields[images]` — можно не указывать

Если этих ключей в файле нет, `renew_fields()` не отправит `auto_delivery` и
`deactivate_after_sale` вообще (они станут `None`), а `fields[images]` добавит пустым сам.
В разделе 402 их и не было в форме — лишние пустые ключи убраны из примера, чтобы запрос
максимально совпадал с тем, который формирует сайт.

### `csrf_token` и `offer_id` — не храните в файле

* `/cache_lots` специально их вырезает.
* `/create_lots` принудительно ставит `offer_id = "0"` (создание нового) и
  `csrf_token` текущего аккаунта. Любое ваше значение будет перезаписано.

## 6. Инструмент: шаблон раздела, генерация пачкой, проверка

В репозитории: `tools/lot_json_tool.py` (запускать из корня Cardinal, нужен доступ к FunPay —
`golden_key` берётся из `configs/_main.cfg`).

### 6.1 Шаблон под раздел

```bash
python tools/lot_json_tool.py template 1089
```

Выведет таблицу полей раздела (подпись, обязательность, допустимые значения select'ов)
и сохранит `template_1089.json` + `template_1089.meta.json`.

### 6.2 Генерация лотов из CSV (Excel)

1. Заполняете таблицу:

| summary_ru | desc_ru | price | amount | secrets |
|---|---|---|---|---|
| Гайд №1 | Строка1\nСтрока2 | 199 | 100 | code1\|code2 |
| Гайд №2 | Другой текст | 250.50 | 50 | |

2. Генерируете JSON:

```bash
python tools/lot_json_tool.py gen --template template_1089.json --rows lots.csv --out lots.json --delimiter ";"
```

Одна строка = один лот. Поля раздела (`fields[type]`, `fields[server]`, …) берутся из шаблона
как есть; если для разных лотов нужны разные значения этих полей — сделайте несколько
шаблонов (например `template_2852_type1.json` и `template_2852_type2.json`) и запустите `gen`
для каждой группы. Колонки CSV с неизвестными именами скрипт не пропустит — это защита от опечаток.

### 6.2.1 Добавление/правка поля во всех лотах

```bash
python tools/lot_json_tool.py add-field lots.json "fields[game]" "Car Dealership Tycoon" --node 402
python tools/lot_json_tool.py set-node lots.json 402
```

Первая команда нужна разделам «Прочие игры» (выбор игры), вторая — чтобы быстро перевести
файл в другой раздел.

### 6.3 Проверка перед загрузкой

```bash
python tools/lot_json_tool.py validate lots.json --template template_1089.json
```

Локально (без запросов к FunPay) повторяет правила `FunPayAPI` и ловит всё, что иначе
вылезет уже после загрузки: `price: "1,5"`, `amount: "9999.0"`, `active: "1"`,
`deleted: "on"`, `secrets` списком, `fields[images]: "abc"`, отсутствие `node_id`,
недопустимые значения полей раздела (если указан `--template`).

## 7. Ограничения плагина, о которых стоит знать заранее

| Ограничение | Деталь |
|---|---|
| Скорость | `time.sleep(1)` на лот → ~1 минута на 60 лотов, 1000 лотов ≈ 17 минут |
| Размер файла | до 20 МБ (`m.document.file_size >= 20971520` → отказ) |
| Только создание | плагин всегда создаёт новые лоты (`offer_id = "0"`), редактировать существующие им нельзя |
| Только обычные лоты | валютные (chips) разделы и «валюта» не поддерживаются |
| Картинки | переносятся только ID (`fields[images]`), сами файлы — нет; при переносе между аккаунтами ID лучше очищать и загружать картинки заново |
| Один процесс | флаг `RUNNING`: пока идёт загрузка, повторный `/create_lots` не запустится |
| Ошибки по одному лоту | при ошибке лот пропускается, процесс продолжается; в конце «✅ Создание лотов завершено!» |
| `form_created_at` не обновляется | см. раздел 4 |

Если плагин упал на каком-то лоте с «❌ Не удалось создать лот» без текста ошибки —
это почти всегда `ValueError` из `LotFields` (цена с запятой, `amount` с точкой,
не-строка в поле). Прогоняйте файл через `validate` до загрузки.

## 8. Чек-лист перед массовой загрузкой

1. Узнали `node_id` нужного раздела (из ссылки).
2. Сняли шаблон: `template <node_id>` — увидели обязательные поля раздела.
3. Заполнили тексты, цену, наличие. `price` — с точкой, `amount` — целое.
4. `active: "on"` (если лот должен сразу продаваться).
5. Решили, чем выдаёте:
   * встроенная автовыдача FunPay → `auto_delivery: "on"` + `secrets`;
   * автовыдача Cardinal → `auto_delivery: ""`, а в `configs/auto_delivery.cfg`
     добавили секцию с названием, совпадающим с `fields[summary][ru]`.
6. Прогнали `validate`.
7. Загрузили 1–2 лота, проверили их на сайте (цена, наличие, активность, текст, EN-версия).
8. Только потом залили весь файл целиком.

## 9. Частые ошибки → причины

| Сообщение бота | Причина |
|---|---|
| `❌ Не удалось создать лот <название>` (без текста) | `ValueError` в FunPayAPI: `price` с запятой/пробелом, `amount` не целое, `secrets` не строка, `fields[images]` не числа, битый `node_id` |
| `… Ошибка: <текст>` | FunPay отклонил форму: недопустимое значение поля раздела, превышена длина, цена ниже/выше допустимой, нет доступа к разделу |
| Лоты создались, но все выключены | `active` не равно `"on"` (например `"1"`, `"true"`) |
| Встроенная автовыдача не работает | нет `auto_delivery: "on"` либо пустой `secrets` |
| Cardinal не выдаёт товар после оплаты | нет секции с таким названием лота в `configs/auto_delivery.cfg` (или не указан `productsFileName`) |
| Лот создался не в том разделе / с пустыми полями | `node_id` от другого раздела либо не переданы обязательные `fields[...]` |
| «❌ Не удалось создать лоты» (одно сообщение на весь файл) | файл не JSON-массив, битый JSON, или объект вместо списка |
